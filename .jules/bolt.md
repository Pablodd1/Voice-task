## 2024-05-15 - In-memory vs Database-level Aggregation Optimization
**Learning:** In the `Claim` and `Call` models, calculating stats like total counts and aggregated amounts was previously done by fetching all rows into memory (`findAll`) and running `filter`/`reduce`. This causes an O(N) memory footprint and leads to potential OutOfMemory issues. Refactoring to a single `findOne` query that utilizes database functions like `COUNT` and `SUM(CASE WHEN...)` yields an O(1) memory footprint and limits data transferred from the DB.
**Action:** When working on future aggregation performance boosts, always prioritize moving data-heavy array filtering out of Node's event loop and into optimized DB-level aggregations (using `sequelize.literal` for complex conditions). Remember to explicitly add comments indicating the performance impact for the Bolt persona.
